# CLI 运行闭环说明

## 这一步解决什么

之前的 Lexer、Parser 和 Interpreter 只能在测试中串起来。这一步增加文件运行入口，让使用者可以从命令行提交一个 `.中` 文件。

## 当前命令

```bash
go run ./cmd/zhongwen 运行 examples/阶段0/最小赋值.中
```

执行流程：

```text
读取文件
    ↓
Lexer
    ↓
Parser
    ↓
Interpreter
    ↓
打印变量环境
```

当前示例输出：

```text
环境[名字=1]
```

## 文件边界

- `internal/runner` 负责连接文件读取和已有组件；
- `cmd/zhongwen` 负责命令参数和用户可见输出；
- Lexer、Parser 和 Interpreter 不知道 CLI 参数，也不直接读取文件。

## 当前限制

- 只接受一个源码文件路径；
- 只支持 `设置 名字 = 1`；
- 只显示变量环境，不执行输出语句；
- 错误信息还没有统一错误编号；
- 暂不支持目录项目和多文件模块。
