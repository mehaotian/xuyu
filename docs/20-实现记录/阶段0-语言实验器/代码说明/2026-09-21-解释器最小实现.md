# 解释器最小实现说明

## 这一步解决什么

AST 已经能够表达一条赋值语句。这一步增加变量环境，让解释器真正执行这条语句，而不是只检查结构。

## 当前执行流程

```text
设置 名字 = 1
    ↓
Lexer
    ↓
Parser
    ↓
AST
    ↓
Interpreter
    ↓
环境[名字=1]
```

## 当前实现

- `Environment` 使用字符串到整数的映射保存变量；
- `Set` 写入变量；
- `Get` 读取变量，并返回是否存在；
- `Run` 按顺序执行程序中的赋值语句；
- `String` 使用排序后的变量名输出稳定结果，方便测试。

## 为什么还没有接 CLI

当前先用测试固定 Lexer、Parser 和解释器之间的边界。CLI 接入会在最小执行链路稳定后单独增加，避免命令行参数、文件读取和语言执行问题同时出现。

## 没有做什么

- 没有变量引用和表达式计算；
- 没有重新赋值的语法测试；
- 没有函数、条件、循环和对象；
- 没有文件读取和输出语句；
- 没有错误恢复。
