# 中文语言规范 v0.1（候选基线）

**状态：** 实验性规范，不代表最终语法冻结
**目标：** 为 Lexer、Parser、解释器和语言实验提供最小一致规则

## 1. 设计原则

1. 中文是源码体验和标识符的一等语言，不是自然语言解析目标。
2. 语义必须确定；编译器不得根据错别字、同音字或上下文猜测用户意图。
3. 完整词优先于极端缩写，关键字数量要受控。
4. 语法必须有可书写、可格式化、可增量解析的结构。
5. 高级特性只有在基础语义稳定后加入。

## 2. 源码与字符规则

- 源码编码统一为 UTF-8。
- 换行统一视为语句和诊断的行边界，工具应兼容 LF 和 CRLF。
- 标识符允许中文、英文字母、数字和下划线；首字符不得为数字。
- 禁止 Emoji、零宽字符、控制字符和容易混淆的 Unicode 组合进入标识符。
- 关键字不能作为普通标识符；如需同名业务字段，必须提供明确的转义机制。
- Unicode 规范化形式应在 Lexer 阶段确定，并在格式化器中保持一致。

## 3. 标点和代码块

建议保留程序员熟悉的表达式符号：`=`、`+`、`-`、`*`、`/`、`==`、`>`、`<`、`.`、`()`、`[]`。

代码块使用冒号加缩进：

```text
如 条件：
    输出 「成立」
否则：
    输出 「不成立」
```

规则：

- 同一文件必须使用一致缩进宽度；格式化器负责统一输出。
- Tab 和空格混用必须报错或在格式化前明确转换，不能静默改变块结构。
- 代码块在 AST 中必须有明确开始和结束，不依赖编辑器显示效果。
- 文字字面量使用 `「」`，同时可提供转义规则；是否支持多行文字需要单独决策。

## 4. v0.1 关键字候选

| 关键字 | 状态 | 语义 |
| --- | --- | --- |
| 定义 | 建议冻结 | 声明函数、对象或入口 |
| 设置 | 建议冻结 | 明确赋值 |
| 如 | 建议冻结 | 条件分支 |
| 否则 | 建议冻结 | 条件的其他分支 |
| 当 | 建议冻结 | 条件循环 |
| 重复 | 建议采用 | 次数循环，避免与集合遍历重载 |
| 遍历 | 建议采用 | 集合或范围遍历 |
| 返回 | 建议冻结 | 返回函数结果 |
| 止 | 建议冻结 | 结束当前循环 |
| 跳 | 建议冻结 | 跳过当前循环迭代 |
| 导入 | 建议冻结 | 导入模块 |
| 抛出/捕获 | 暂缓 | 错误处理，需先确定错误模型 |
| 获取、增加、减少、更新 | 实验性 | 可作为语法糖或标准库操作，不宜过早设为核心关键字 |

原始材料中的 `遍` 同时表示“重复次数、遍历集合、范围循环”。这种表达简短但重载过多。建议先采用不同语法形态，待真实代码实验后再决定是否合并。

## 5. 建议语法骨架

下面是面向实现的非正式 EBNF，完整语法需要在 Parser 原型中固化。

```text
文件       ::= 声明*
声明       ::= 导入声明 | 定义声明
导入声明   ::= "导入" 模块路径
定义声明   ::= "定义" 名称 参数列表? ":" 代码块
代码块     ::= 缩进 语句+ 反缩进
语句       ::= 赋值 | 条件 | 循环 | 返回 | 表达式
赋值       ::= "设置" 左值 "=" 表达式
条件       ::= "如" 表达式 ":" 代码块 ("否则" ":" 代码块)?
循环       ::= "当" 表达式 ":" 代码块
           | "重复" 表达式 "次" ":" 代码块
           | "遍历" 表达式 "为" 名称 ":" 代码块
           | "遍历" 表达式 "到" 表达式 "为" 名称 ":" 代码块
返回       ::= "返回" 表达式?
表达式     ::= 字面量 | 名称 | 属性访问 | 调用 | 一元表达式 | 二元表达式 | 列表 | 映射
属性访问   ::= 表达式 "." 名称
调用       ::= 名称 "(" 参数值* ")"
```

## 6. 控制流语义

### 6.1 条件

```text
如 玩家.生命 > 0：
    输出 「存活」
否则：
    输出 「死亡」
```

条件表达式必须得到布尔值。是否允许“真值转换”待类型系统实验决定；建议 v0.1 禁止整数、文字等隐式转换。

### 6.2 条件循环

```text
当 玩家.生命 > 0：
    战斗()
```

循环条件每次迭代前求值。`止` 和 `跳` 只作用于最近的循环，跨函数使用必须报错。

### 6.3 次数循环

```text
重复 10 次：
    输出 「你好」
```

次数必须是整数；负数、溢出和运行时动态次数的行为必须在类型/运行时测试中确定。

### 6.4 集合与范围遍历

```text
遍历 用户列表 为 用户：
    输出 用户.名字

遍历 1 到 100 为 当前：
    输出 当前
```

循环变量必须显式命名，禁止依赖隐含的 `当前`。这样可以避免嵌套循环中内外层变量冲突，也是对原始 `遍 用户列表` 候选语法的必要收敛。

## 7. 变量、函数与对象

### 7.1 变量

```text
定义 主程序：
    设置 年龄：整数 = 18
    设置 名字：文字 = 「张三」
```

是否允许顶层变量、变量可变性和声明时省略 `设置`，需在类型系统实验中决定。赋值目标必须是可写变量或属性。

### 7.2 函数

```text
定义 攻击(攻击者：玩家, 目标：敌人) -> 整数：
    设置 伤害：整数 = 攻击者.攻击力
    减少 目标.生命 伤害
    返回 伤害
```

建议将 `增加/减少` 先实现为标准库或编译器语法糖，并明确其读写、溢出和并发语义。核心赋值始终使用 `设置`，避免同一概念有多个不可组合的写法。

### 7.3 对象

```text
定义 玩家：
    名字：文字
    生命：整数 = 100
    等级：整数 = 1

    定义 攻击(目标：敌人)：
        减少 目标.生命 等级 * 10
```

对象模型仍需补充：构造器、继承/组合、方法接收者、属性可见性、接口、空值和对象相等性。v0.1 建议只支持结构化对象和方法，不支持继承和泛型。

## 8. 类型系统最低规则

### 8.1 类型集合

基础类型：整数、小数、文字、布尔、空值。
复合类型：列表、映射、对象。

### 8.2 静态检查

- 变量在使用前必须声明或由明确规则推导。
- 赋值类型必须兼容；不允许文字自动转换为数字。
- 函数参数个数和类型必须匹配。
- 属性必须存在且可访问。
- 所有路径的返回值必须满足函数声明。
- 条件、循环条件必须为布尔。

### 8.3 明确未决项

以下项目必须在冻结对象和模块前定稿：

- 空值是否使用 `可空<类型>` 或独立类型；
- 整数位宽、溢出和除零行为；
- 可变/只读变量和参数传递方式；
- 类型推导范围和错误显示方式；
- 泛型、接口、联合类型和模式匹配；
- 错误是值、异常还是两者并存。

## 9. 模块和包

建议使用：

```text
导入 网络
导入 游戏.战斗
```

模块路径、循环依赖、可见性、初始化顺序和重命名规则必须在 MVP 之前写入规范。公共注册表不应早于这些规则稳定。

## 10. 中文输入和 AI 边界

IDE 可以提供：

- 拼音到关键字和符号的搜索；
- 编辑距离和作用域感知的候选；
- 代码模板、补全和错误解释；
- 自然语言到代码的草稿生成。

编译器不能接受：

- 自动修正错别字后的未确认源码；
- 根据上下文选择同音词；
- 依赖在线 AI 才能完成解析；
- 模糊匹配多个合法符号。

## 11. 语法冻结前必须完成的实验

1. 用至少 5 个真实任务写出 500～1000 行示例代码；
2. 对嵌套循环、属性访问、错误分支和模块导入做语法压力测试；
3. 对中文输入法、拼音搜索和英文混用进行编辑器任务测试；
4. 统计每个候选关键字的歧义、输入长度和错误率；
5. 记录迁移成本，确认语法不是只适合演示代码。
