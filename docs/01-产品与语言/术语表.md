# 编译器与工具链术语表

本表将原材料中的术语转为项目团队共用的简明定义。术语本身不是需求，只有在产品需求或技术路线中明确范围后才构成承诺。

## 1. 编译器核心

| 术语 | 中文 | 项目中的理解 |
| --- | --- | --- |
| Lexer | 词法分析器 | 将 UTF-8 源码切成带位置的 Token |
| Token | 词法单元 | 关键字、标识符、数字、符号等最小语法单位 |
| Parser | 语法分析器 | 按语言规则将 Token 组成 AST |
| AST | 抽象语法树 | 表达源码结构的树，供语义分析使用 |
| Semantic Analysis | 语义分析 | 名称解析、作用域、类型和控制流检查 |
| Type Checker | 类型检查器 | 判断表达式和调用是否符合类型规则 |
| IR | 中间表示 | 连接语言前端、解释器和多个后端的内部程序表示 |
| Compiler | 编译器 | 将源码转换为可执行或可继续编译的形式 |
| Interpreter | 解释器 | 直接执行 AST 或 IR，作为早期参考实现 |
| Backend | 后端 | 将 IR 转成 Native、WASM 等目标形式的组件 |
| LLVM | 编译器基础设施 | 可协助目标代码、优化、调试信息和多架构支持的基础设施 |

## 2. 运行时与执行

| 术语 | 中文 | 项目中的理解 |
| --- | --- | --- |
| Runtime | 运行时 | 程序运行所需的对象、内存、文字、I/O 和系统交互基础 |
| Standard Library | 标准库 | 面向用户的文件、JSON、HTTP、时间等稳定 API |
| GC | 垃圾回收 | 自动识别不可达对象并回收内存的机制，具体方案待决 |
| JIT | 即时编译 | 程序运行时将热点代码临时编译为机器码，MVP 不需要 |
| FFI | 外部函数接口 | 调用 C、系统库或宿主环境函数的边界 |
| ABI | 应用二进制接口 | 函数调用、值表示、错误和运行时之间的二进制契约 |
| WASM | WebAssembly | 可在浏览器或沙箱中执行的目标格式 |
| Native | 原生目标 | 面向 Windows、macOS、Linux 等平台的机器代码产物 |

## 3. 编辑器和开发工具

| 术语 | 中文 | 项目中的理解 |
| --- | --- | --- |
| Tree-sitter | 增量解析框架 | 为编辑器提供快速、可容错的语法树；不能替代编译器语义源 |
| LSP | Language Server Protocol | 编辑器与语言服务器通信的协议 |
| Language Server | 语言服务器 | 提供补全、诊断、跳转、引用和重构能力的程序 |
| IDE | 集成开发环境 | 编辑器、项目管理、运行、测试、调试等能力的组合 |
| CLI | 命令行界面 | 创建、运行、检查、测试、构建、发布语言项目的命令工具 |
| Formatter | 格式化器 | 按稳定规则重排缩进、空格和换行，不能改变语义 |
| Debugger | 调试器 | 断点、单步、变量和调用栈查看工具，属于后期能力 |
| SDK | 软件开发工具包 | 为扩展、插件或外部集成提供的接口集合 |
| API | 应用程序接口 | 程序可调用的函数、模块或服务边界 |

## 4. 工程与生态

| 术语 | 中文 | 项目中的理解 |
| --- | --- | --- |
| Module | 模块 | 可独立解析、导入和构建的源码单元 |
| Package | 包 | 可分发的模块集合及其元数据 |
| Registry | 注册表 | 发布和下载包的服务 |
| Lockfile | 锁定文件 | 记录精确依赖版本和校验和，保证可复现构建 |
| Toolchain | 工具链 | 编译器、运行时、标准库、格式化器、测试器和发布器的整体 |
| Reproducible Build | 可复现构建 | 相同源码和依赖生成可验证一致的产物 |
| Cross Compilation | 交叉编译 | 在一个平台构建另一个目标平台的产物 |
| Symbol ID | 符号 ID | Lexer/解析后用于高效引用符号的内部标识，避免运行时反复比较中文字符串 |

## 5. 项目架构记忆图

```text
源码
  -> Lexer/Token
  -> Parser/AST
  -> 语义分析/类型检查
  -> IR
  -> Interpreter 或 Backend
  -> Runtime + Standard Library
  -> CLI/IDE/发布产物
```

```text
编辑器 -> LSP -> Language Server -> 共享语义分析
编辑器 -> Tree-sitter -> 编辑态语法树
```

## 6. 术语使用约束

- “编译”不等于“已经能生成独立程序”；必须说明目标后端和运行时依赖。
- “跨平台”必须列出平台、架构、标准库覆盖和测试状态。
- “支持 IDE”必须列出补全、诊断、跳转、格式化和调试分别达到什么程度。
- “有包管理”必须说明版本、校验、来源、锁定和安全策略。
- “AI 辅助”不等于“AI 参与编译”；编译器行为必须在无 AI 时完全确定。
