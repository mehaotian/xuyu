# 阶段 0：语言实验器

## 阶段目的

用最少的代码回答一个问题：这门语言的基本中文表达，能不能被稳定地切分、解析和运行。

本阶段不追求完整，不接 LLVM，不做包管理，也不做完整 IDE。重点是让参与者看懂从源码到执行结果的每一层。

## 阶段完成标准

- 有一个可以运行的 Go 项目；
- 有中文源码示例和对应测试；
- Lexer、Parser、AST、解释器之间的边界清楚；
- 支持的语法都有中文说明和失败案例；
- 新参与者可以按照文档完成一次小改动。

## 步骤清单

### 0.1 项目骨架和开发入口

**目标：** 创建最小 Go 模块、命令入口、示例目录和测试入口。
**不做：** 不解析源码，不定义完整 Token，不引入第三方库。
**停点：** `go test ./...` 可以运行，命令可以显示版本或帮助。

### 0.2 Token 类型实验

**目标：** 定义最小 Token 类型、源码位置和打印方法。
**不做：** 不读取文件，不实现完整 Lexer。
**停点：** 测试可以构造并打印关键字、标识符、整数和符号 Token。

### 0.3 Lexer：读取最小词法单元

**目标：** 识别空白、一个中文关键字、中文标识符、整数和等号。
**不做：** 不处理所有关键字、文字、Unicode 特殊情况和错误恢复。
**停点：** 固定输入的 Token 序列测试通过，非法字符有位置错误。

### 0.4 AST 与 Parser：表达一条设置语句

**目标：** 定义标识符、整数和赋值语句的 AST，并解析一条 `设置 名字 = 1`。
**不做：** 不实现条件、循环、对象、类型检查和表达式优先级。
**停点：** Parser 能把一条源码转成可打印 AST，并能报告缺少或多余 Token。

### 0.5 计划调整说明

原计划把 AST 和 Parser 分成两个步骤，实际实现时将它们合并，因为单独定义 AST 还不能形成可验证的源码结构。合并没有扩大语法范围，只是让这一小段链路一次闭合。后续仍保留原编号，方便对照早期记录。

### 0.6 解释器：运行整数赋值

**目标：** 将 AST 写入一个简单环境并能查看结果。
**不做：** 不做对象、函数、垃圾回收和文件 I/O。
**停点：** 示例源码运行后得到确定的变量值。

### 0.7 第一次阶段复盘

**目标：** 用真实小例子检验关键字、错误信息和目录结构。
**不做：** 不顺手加入下一批语法。
**停点：** 写出阶段总结、保留问题和下一阶段提案，等待确认。

### 0.8 CLI 最小运行闭环

**目标：** 读取一个 `.中` 文件，依次调用 Lexer、Parser 和 Interpreter，并显示变量环境。
**不做：** 不增加新的语法，不实现输出语句、变量引用或表达式。
**停点：** `中文 运行 examples/阶段0/最小赋值.中` 能得到确定结果，并有命令行测试。

### 0.9 阶段 0 结束评估

**目标：** 回看从源码到执行结果的完整链路，确定阶段 0 是否达到可继续共建的标准。
**不做：** 不在评估过程中临时加入新的语言特性。
**停点：** 形成阶段总结，列出保留问题，并明确下一阶段只做的一个小目标。

### 0.10 语句边界实验

**目标：** 研究换行、缩进或显式分隔符如何表示多条语句。
**不做：** 不实现变量引用、表达式、条件和循环。
**停点：** 形成一份有样例、有取舍理由的语句边界决定，再开始多条赋值实现。

### 0.11 Lexer 保留换行 Token

**目标：** 让 Lexer 保留换行，Parser 暂时支持一个文件中的多条整数赋值。
**不做：** 不实现变量引用、表达式、条件、循环、分号和缩进 Token。
**停点：** 多条赋值、空行和文件末尾没有换行的测试通过。

### 0.12 变量引用实验

**目标：** 支持将已经存在的整数变量赋给另一个变量，例如 `设置 总数 = 名字`。
**不做：** 不加入加减乘除、比较、函数调用和隐式创建变量。
**停点：** 已定义变量可以被读取，未定义变量有明确错误；完成后暂停。

### 0.13 / M1 整数表达式闭环

**目标：** 一次打通整数四则运算、括号、优先级、变量运算和除零错误。
**不做：** 不加入一元负号、小数、比较、布尔逻辑、文字和隐式类型转换。
**停点：** Token、AST、Parser、Interpreter、CLI、测试、示例和文档形成完整闭环，完成后暂停。
